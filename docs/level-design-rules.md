# 레벨 디자인 공통 규칙

모든 스테이지의 지형, 적 배치, 전투 흐름에 적용하는 기준이다. 스테이지별 연출이나 이동 모드의 예외는 각 스테이지 데이터에 이유와 함께 남긴다.

## 지형과 발사체

| 요소 | 이동 규칙 | 발사체 규칙 | 레벨에서의 역할 |
| --- | --- | --- | --- |
| 발판 (`platform`) | 아래에서 통과하고 위에 착지하는 일방통행 지형 | 플레이어와 적의 일반 탄이 모두 통과 | 높이, 이동 경로, 사격 각도 선택 |
| 벽 (`wall`) | 모든 면이 막힌 지형 | 일반 탄을 막음 | 넘거나 대시해 통과하는 장애물, 필요한 경우의 엄폐물 |
| 구덩이 (`pit`) | 바닥이 끊기며 낙하 피해를 받음 | 해당 없음 | 의도적으로 배치한 이동 과제 |

- 발판 아래에 비행 적을 둔다는 이유만으로 안전한 구조가 되지 않는다. 발판은 탄막을 막지 않는다.
- 탄을 막아야 하는 전투 구간에는 발판이 아니라 벽을 사용한다.
- 발판은 플레이어가 다른 높이에서 이동하거나 쏠 수 있게 만들기 위해 둔다. 반드시 모든 비행 적 바로 아래에 둘 필요는 없다.
- 스테이지 5는 비행 이동이므로 발판, 벽, 구덩이를 두지 않는다. 전면 문만 경계로 사용한다.

## 이동 기준

현재 지상 이동 수치에서 계산한 기준은 다음과 같다.

| 항목 | 값 |
| --- | ---: |
| 이동 속도 | 300 px/s |
| 점프 속도 | 560 px/s |
| 최대 점프 높이 | 약 130.7 px |
| 같은 높이에서 최대 점프 거리 | 280 px |
| 대시 거리 | 약 129.2 px |
| 편안한 필수 점프 간격 | 196 px 이하 |
| 한계 점프 간격 | 266 px 이하 |

- 필수 진행에 필요한 점프는 기본적으로 편안한 간격 안에 둔다.
- 한계 점프는 선택 경로나 보상이 있을 때만 사용한다.
- 발판 하나가 닿는지만 보지 않고, 그 발판에서 다음 발판이나 바닥으로 안전하게 이어지는지도 확인한다.
- 벽은 발판처럼 밟고 올라가기 위한 계단이 아니다.

## 구덩이와 전투

- 스테이지 1에는 구덩이를 두지 않는다.
- 구덩이를 처음 만나는 구간은 적과 겹치지 않는 여유 구간으로 둔다.
- 이후에는 적 사격, 추적, 이동 동선이 겹칠 때에만 구덩이를 사용한다. 단순히 바닥을 비워 난도를 올리지 않는다.
- 지상 적을 구덩이 위에 생성하지 않는다.

## 적 배치와 진행

- 새 적 유형은 처음에는 다른 위협과 겹치지 않게 배치한다.
- 적 유형을 처음 마주친 뒤에 조합전을 배치한다.
- 적 생성 좌표만으로 거리를 판단하지 않는다. 실제 사거리, 추적 속도, 화면에 동시에 보이는 수를 함께 확인한다.
- 방의 마지막 적 뒤에는 다음 방 또는 보스에 들어가기 전 정리할 여백을 둔다.
- 각 스테이지는 낮은 압박과 높은 압박이 번갈아 오도록 구성한다. 전투만 연속되거나 휴식만 이어지지 않게 한다.

```powershell
pnpm --filter @soot/client exec vitest run src/game/config/rooms/reachability.test.ts
```

이 테스트는 점프 가능 거리, 구덩이, 적 생성 좌표 등 데이터 오류를 잡는다. 적의 실제 추적, 탄막, 화면 압박은 플레이로 별도 확인한다.
